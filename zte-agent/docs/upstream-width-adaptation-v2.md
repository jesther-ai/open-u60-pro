## 1. 推荐结论与边界

推荐采用：**固定稳定锚点 + 单候选挑战 + 同口径的新鲜窗口 + 每候选退避 + 全局探索预算**。

这不是把 hostapd ACS 移植到 STA，也不是实现新的 MCS 速率控制算法。它只调整已经连接的上游 BSS 的 STA operating width，不改变主信道、不控制远端 AP 的逐帧速率，不主动调节本机热点的参数。

- 2.4 GHz 候选为 20/40 MHz；5 GHz 为 20/40/80/160 MHz；还须受本次协商、合法信道组合和驱动执行能力约束。
- 不新增热点 AP 自适应、不修改国家码、不强制 MCS/NSS/功率、不启用蜂窝、不重启厂商服务。
- 不做后台测速、周期性全信道扫描或 monitor 抓包，不创建第二个网络控制进程。
- 不承诺始终找到实际最快的互联网路径；在业务不足、统计不可信或外部瓶颈存在时，保持稳定选择是正确结果。
- 原始调查证据、公开算法建议和工程初始参数分开记录；下文参数不是已经通过真机标定的结论。
- 历史记录的 5 GHz DIRECT 约 213–246 Mbit/s、Mihomo 约 119–131 Mbit/s 只用于提醒可能存在转发/代理瓶颈，不是本轮复测值；PHY 提升不能保证跨过这些瓶颈。

## 2. 本轮硬件能力探测

只对用户已授权 USB ADB 的现有设备执行查询；没有进行扫描、连接、改宽度、测速、LL_STATS_SET、统计清零、安装或重启。现有 `ll_stats` 已可读，本轮没有额外启用它。部分 getter 会触发固件查询或诊断日志，不等于零开销。

### 2.1 平台与并发

| 项目 | 本轮证据 | 对方案的约束 |
|---|---|---|
| CPU / 内核 | 4 个 ARM `0xd05` 核；`5.15.194-perf`、aarch64 | 延续现有低频 watcher，不需要逐包用户态算法 |
| 无线驱动 | 启动日志 `v5.2.1.110D`；PCI `17cb:1107`；ethtool 报 `cnss_pci` | SDX75 是平台信息，不能直接当作无线芯片型号；方案不依赖未经确认的商业芯片名称 |
| 当前 STA | 5220 MHz，operating width 160 MHz；RX/TX 报 HE-MCS 9、HE-NSS 2、1921.5 Mbit/s | 160 MHz / 2 NSS 有当前运行证据，但 PHY 速率不是业务吞吐 |
| 当前热点 | 5 GHz 热点与 STA 同为 5220 MHz，热点 80 MHz；2.4 GHz 热点 2462 MHz / 40 MHz | 同一 radio 上的 STA/AP 统计归属必须区分；不能把热点业务一律当作污染并剔除 |
| 并发 | `ll_stats` 有两个 radio；并发诊断记录 DBS=1、SBS=0；5220 MHz 的 AP/STA 都在 MAC 1，2462 MHz 的 AP 在 MAC 0 | radio 归属发生变化时必须重置测量 epoch，不能跨 radio 相减 |
| PHY 宣告 | 暴露 2.4/5 GHz、HE160，含一些不完整/可疑的 HE RX NSS 与 EHT 项 | 不据此声称 8 NSS、320 MHz、6 GHz、MLO 或 puncturing 可用；候选以实际协商和可验证控制为准 |

### 2.2 能读到，不等于能用于决策

| 输入 | 本轮实际结果 | V2 定位 |
|---|---|---|
| `/sys/class/net/u60sta0/statistics/*` | RX/TX 字节、包计数非零且增长；一次 RX 约 949.6 MB，后续约 974.3 MB | 自有接口流量和测量窗字节的首选来源；不把它等同于应用层 goodput |
| `iw ... station dump` RX 字节/包 | 都为 0，与 netdev 非零计数冲突 | 当前接口路径判为缺失，不能将 0 当作没有接收 |
| 同一 station dump 的 RX bitrate / signal | 有 HE 速率和约 −44 至 −49 dBm 信号 | 低可信度速率后备、链路上下文；不是平均吞吐、不是丢包统计 |
| STA `ll_stats` radio/channel 时间 | 多次读取持续增长；两个相邻快照的 radio on_time 增加约 117 ms | 有效的共享无线电观测候选；要校验 scope、计数重置、读数时间与 radio 身份 |
| STA `LL_STATS_IFACE` WMM AC | `tx_mpdu`、`rx_mpdu`、`retries`、竞争时间、样本数有数据；`tx_pending_msdu` 本轮为 0 | 有望提供本接口上传健康度/竞争辅助信号；非零字段仍须受控负载验证语义，队列字段不能因出现而认定能反映积压 |
| `LL_STATS_PEER_ALL` 按速率统计 | 16 条 rate entry，5 条有非零 TX；RX 全为 0；存在 TX retries | TX 侧能力比旧交接的笼统描述更丰富；仍无可靠的 per-rate 下行成功/失败分布 |
| `iw station dump` TX retries | 为 0，而 LL AC retries 已有约 5200 | 不混用不同接口的成功/重试计数；零值不证明无重传 |
| `iw ... survey dump` | 有 active/busy/tx/noise，但跨多次读取全部保持不变，包括当前信道；所有噪声均 −96 dBm | 本次观测中不能作为实时负载输入；可能是扫描相关缓存，原因未证实。无新鲜度证据前禁用实时 ACS 评分 |
| `iwpriv ... get_chwidth` | 两次返回 0；同期 `iw dev info` 一直 160 MHz，PHY 也报 160 MHz | 私有 getter 不能当作当前 operating width 的权威读回；优先保留现有 `iw info` 验证路径 |
| `iwpriv ... get_nss` / `getSNR` | 2 / 52 | 可作诊断，不能据此接管 NSS 或判定吞吐 |
| STA `mib_stats` | 读取返回 `Bad address` | 当前不可用，不能设计成必需输入 |
| 热点 `wlan2/ll_stats` | 读取返回 `Invalid argument` | 不假设每个 vdev 都已提供独立 LL 数据；不为本提案擅自改变统计配置 |
| `ethtool` 统计 | `supports-statistics: no` | 不能依赖 ethtool 获得遗漏的 per-peer airtime |

本轮 STA LL 查询的两次主机 ADB 往返约 27/29 ms。这不是固件查询的独立耗时，也不是最坏时延保证。只读取过少量快照，没有验证满负载、切换期间、休眠、重关联后的统计稳定性。

### 2.3 可复查的脱敏数值

- survey 当前 5220 MHz：active=40205 ms、busy=3462 ms、TX=1356 ms，跨本轮重复读取未变。
- 同期 LL 的 5220 MHz channel on_time：1488647 → 1559881 → 1559998 → 1774884 ms；RX 时间也增长。两种接口的数值不可互相拼接。
- 首次 netdev：STA RX=949589677 B，5 GHz 热点 TX=948725152 B；STA TX=150407619 B，热点 RX=151780277 B。可见转发业务相关，但不能以这个相关性证明无线接收时间属于哪个 vdev。
- 本轮没有 STA 空闲/热点单独上传的受控实验，因此不把“共享 airtime 偏差只会压小差距”当作已证实结论。

## 3. 公开算法：借鉴机制，不照搬适用前提

详细源码与原始资料链接见[算法研究](upstream-adaptation-algorithm-research.md)。

| 算法/接口 | 借鉴什么 | 不照搬什么 |
|---|---|---|
| hostapd survey-based ACS | 验证测量字段是否具备；考虑合法信道几何、干扰与测量新鲜度；扫描邻居只作为先验 | ACS 的主任务是 AP 选工作信道，不是已关联 STA 选择最优接收带宽；本机 survey 当前不刷新。QCA WMI 的 `cca_busy_time` 定义还明确排除 TX，不能直接套 ACS 的 busy−TX 公式 |
| Linux Minstrel / Minstrel-HT | 成功交付比名义 PHY 速率重要；有成本约束的探索；近期统计和平滑；保留可靠选择 | 它基于发送端逐速率尝试/成功反馈。本机 STA 的 TX retries 不等于上游 AP 的下行重试；不移植其逐包时间尺度或 MCS 表 |
| Intel `iwl-mvm-rs` | 当前表与候选表分离；充分测量后替换；候选失败回到旧选择；探索有阶段 | 并不是为 qcacld 提供通用 160/80/40/20 MHz 遍历器，也不能绕过固件速率控制 |
| nl80211 / Android HAL / QCA LL 结构定义 | 明确 last RX bitrate、peer RX_DURATION、radio rx_time、WMM TX 统计的不同 scope | 字段名字、读取成功或单次非零，不等于该固件实现了对应语义 |

因此推荐的是一个小型、保守的在线选择器，不是“ACS + Minstrel + bandit”大杂烩。候选最多四个，简单轮换足以避免饿死；尚无必要上 UCB、Thompson Sampling 或强化学习。

特别注意两项源码边界：

- QCA WMI 的 `wmi_channel_stats.cca_busy_time` 注释为包含 RX、不包含 TX；hostapd 处理的 survey busy 语义不能直接套到它上面。WMI 定义的具体版本与原始链接见[算法研究](upstream-adaptation-algorithm-research.md)；本机语义仍需验证。
- 某公开 qcacld 实现的 `WMI_VDEV_PARAM_CHWIDTH` getter 返回 host 的 `config.chwidth` 缓存，而非实时协商读数；同一公开版本的 setter 能力又与本机 160 MHz 不一致。它可以解释为什么不该盲信 getter，但**不能当作这版固件根因或 STA-only 无副作用的证明**。[公开 getter 实现](https://android.googlesource.com/kernel/msm-modules/qcacld/+/c679e05584c4ca427b4baf0a677f56bd42c3264a/core/wma/src/wma_main.c#340)。

## 4. 对交接材料第 7 节的采纳与修订

### 完全采纳

1. 复查不再从最宽档开始覆盖历史赢家。
2. 回滚锚点在整轮挑战期间固定。
3. 每轮只有一个挑战者；失败不排除其他更窄候选。
4. airtime 评分改为窗口原始计数求和，增加样本新鲜度。
5. 不周期性扫满四档，不降低单个噪声样本的安全门槛来强行得出结论。
6. 不将 CCA、RSSI、重试、吞吐揉成不透明的综合分。
7. UI 只补充简洁状态和原因，不新造图表或复杂配置。

### 需要修订/加条件

- **共享 radio 偏差不保证只让算法更保守。** 两个窗口的热点上传或其他接收活动不同，就可能改变相对排序；统一乘一个“低权重”也不会消除这种偏差。必须做负载对照，必要时回到锚点复核。
- **不能丢弃所有“热点忙”的样本。** 正常中继下载本来就伴随热点发送和客户端 ACK。需要关注业务方向比例突然变化、scan/radio 切换等上下文，而不是“有热点流量就无效”。
- **PHY fallback 不按字节加权声称平均接收速率。** `rx bitrate` 只是最后一帧；把这一个值赋给整个间隔的字节不能还原逐帧分布。最多对新鲜、有业务的快照作时间统计，并明确低可信度。
- **早停必须在 settling 之后、有足够证据时触发。** 不能把切换后的爬速、短空窗或旧 rate 快照当作候选失败。
- **TX 能力不应完全放弃。** 本轮发现 STA LL AC / per-rate TX 有数据；先验证后作为上传防退化保护，不用整个 radio `tx_time` 计算“STA 上传效率”。
- **`tx_packets` 不足以证明下行需求。** 它包含 ACK、DNS、ARP/控制及重试业务，不证明远端有数据可下发，也不能区分认证页面与坏无线。V2 默认不加入无基线的自动“停滞自救”。
- **不通过 BSSID 邻近推断同一台路由器。** 即使只显示提示，也容易把不同 AP/网络认错。跨 BSS/频段是后续单独策略，不偷偷自动换网。
- **不写死 −70 dBm 作为 5 GHz 必胜条件。** 同 SSID、同安全能力、历史实效、并发拓扑都要考虑；同频中继、WAN/代理瓶颈也影响收益。
- 第 7 节的 CSS“只剩 6 字节”已过时：本轮文件 48633 B，距离 48 KiB 还有 519 B。即便如此仍无需为了本功能扩展 CSS。

## 5. V2 的状态与安全不变量

### 5.1 必须分开的概念

- **actual_width**：驱动已读回的当前 operating width。
- **anchor_width**：本轮试验前的稳定选择；试验期间不变。
- **baseline_window**：刚在锚点完成的新鲜测量，不是数小时前的缓存分数。
- **challenger_width**：本轮唯一候选。
- **candidate_history**：每个候选的最近结果、失效时点、独立退避；没有赢家分数就不装作有。
- **measurement_epoch**：连接代次、主信道、radio 身份、计数来源、计数连续性及实际宽度的上下文。

仅首次关联、尚未测量时，要区分“当前可以维持连接的起点”和“本会话已测量的稳定锚点”。历史缓存可以指导起点，不能替代本会话的 baseline。

### 5.2 一次挑战

1. **等待证据**：只有当前 STA 有真实业务、连接稳定、无恢复/切换冲突时才打开测量窗。
2. **刷新锚点**：在 actual=anchor 时完成 baseline。数据不足就继续保持，不先切过去再猜原来的性能。
3. **选一个到期候选**：必须在合法能力范围内；优先未测/过期候选，相邻档位用于排序，不允许某档反复占用所有探索机会。
4. **申请并读回**：复用 Controller 的有限重试与验证；成功返回值不等于已经生效。跨切换区间不计入任何一方。
5. **settling**：先等待读回，再给 AP 速率控制至少原先约 6 s 的适应期；并要求有相应业务观测，不在一段长空闲后立刻拿首帧判胜负。
6. **测量候选**：同一种统计来源、同一 epoch、有限时间内收集窗口。坏性能是负证据，但不能把“没有数据”伪造为零分。
7. **提交或回滚**：明显胜出且保护条件未恶化才提交；失败、超时、不可比较都回到原锚点。回滚仍须读回确认。
8. **按结果冷却**：只有确定输了才增加性能退避；证据不足不是“这个候选永远差”。执行失败使用独立的操作冷却。

### 5.3 不可破坏的规则

- 改分数来源、完成一次候选采样、准备下一步，都不能覆盖 rollback anchor 或延长既定试验截止时间。
- 只有候选完成比较，才把它提升为新的 anchor；先已读回并不等于已胜出。
- 缺少读回时不宣称已回滚，不将未知状态写入缓存；停止进一步探索并显式报告无法确认。不能承诺驱动失效时一定恢复。
- 上游掉线、DHCP/网络恢复、用户操作优先于调优；旧会话的迟到读数/动作必须被代次检查丢弃。
- 外部改宽度、主信道或 radio 归属变化时，终止旧实验、废弃旧窗口，不能盲目把旧锚点写到新环境。
- STA 调宽度可能触发固件并发策略；代码“不写 AP”不等于已经证明 AP 无副作用，真机验收要观察客户端中断。

## 6. 测量与决策

### 6.1 保留可解释的三个量

```text
接收交付速率 R = 8 × ΣΔSTA_rx_bytes / 窗口墙钟时长
共享接收空口效率代理 E = 8 × ΣΔSTA_rx_bytes / ΣΔradio_rx_time
后备 P = 有实际接收业务时的新鲜 RX bitrate 快照统计
```

- R 是本接口交付速率，不证明链路饱和，也不是网页测速结果。
- E 仍是 proxy，不是精确的 per-STA airtime efficiency；它不能完整表示竞争等待、每种失败帧或其他 vdev 的占用。
- P 是低可信度后备，不能和 E 比大小，也不反推成下行 PER。
- 不给三个量任意系数后相加。E 的适用性通过真机校准；R 用于同负载实验验证/异常保护，P 用于后备和上下文解释。

### 6.2 窗口规则

建议首轮实现以现有 3 s watcher 节拍为基础：

| 参数 | 初始建议 | 说明 |
|---|---|---|
| 基线/候选目标窗 | 约 12 s，必要时延长至 30 s | 不是固定四个跨任意时长的离散点 |
| 最小接收证据 | 保留窗口平均至少约 1 Mbit/s 的保守门槛 | 改为累计字节/窗口时长，不要求每个 tick 都独立达标 |
| 最小 airtime | 整个有效窗口累计至少 100 ms | 不再要求每个 3 s 都达到 100 ms；未达到则无结论 |
| 新鲜度 | 基线与候选必须相邻；长空档或上下文变化后重建 | 初始可用 30 s 基线有效期、6 s 无有效观测间隔作为实验参数 |
| 切换收益 | 至少 15% | 先保留已有门槛；波动大或接近门槛时不切，不急着调小阈值 |
| 快速认输 | settling 后两个有效观察明显低于新鲜锚点的一半，且累计证据合格 | 仅有零字节/缺失计数不能触发这种性能结论 |
| 挑战截止 | 从首次申请候选起 45 s，不续期 | 包含执行等待和 settling；到时发起回滚，不是保证此刻已经回滚成功 |
| apply/rollback 验证 | 保留 6 s 重试、最多 3 次、18 s 窗口 | 回滚另有最多 18 s 验证；失败进入未确认状态而不是继续尝试下一档 |

这些参数共同约束实验，不能分别解释为每阶段都保证获得完整时间。延迟执行会压缩候选测量时间；证据不足时宁可回滚。

原始字节与 airtime 要有对齐的端点：开始读 LL 后先建立基线，不能把之前只有 netdev 的区间追溯配给 LL 时间；计数倒退、溢出语义不明、radio 迁移和切换交叉区间重建 epoch。不要用 `saturating_sub` 隐藏计数重置后继续累计。

radio 选择还须保留其身份：现有实现按目标频率上的历史累计 on_time 最大值挑 radio，迁移后历史最多不一定代表当前归属。应使用经验证的当前映射，并以当前信道时间增量等交叉检查；不能唯一判断时本轮无结论，不跨 radio 拼接。不要为此每 tick 读取会打印诊断日志的 `pm_cinfo`。

### 6.3 比较置信度：先做简单分级，不伪造统计保证

- **可比较**：同来源、同连接/radio、样本足够、业务方向与环境没有明显突变；以窗口 E 和 15% 门槛判断。
- **可疑**：A/B 之间独立上传、扫描量、信号或业务方向明显变化；不因“热点忙”本身拒绝，而是需要额外复核或暂缓结论。
- **无效**：计数不连续、读回未确认、来源改变、样本过旧/不足；不能参与胜负判断。

首版不宣称统计学 95% 置信区间。运行时遇到可疑结果就回滚、延期，不为凑结论连续切换。阶段 B 的受控校准用 A-B-A：返回锚点取得 A2，若 A1/A2 自身明显变化，则这次对照无结论。先验证简单 A/B 在可比较窗口中是否可靠；只有校准证明有必要，才考虑以后把有限复核加入运行时，不能每次固定 A-B-A-B。

PHY fallback 必须重新建立同口径基线，保留回滚锚点，并要求重复的新鲜证据，不能用一帧高 PHY rate 覆盖高可信度历史。必要字段全部不可用时保持当前配置。

### 6.4 TX 健康度先作为保护条件

待真机确认后，从同一次 STA LL 查询取 AC/per-rate TX 的变化：

- 正常化的重试强度与丢失事件趋势；先核对分母与计数定义，不擅自命名为精确 PER。
- 有足够样本时的竞争等待变化；累计 min/max/avg 不能直接相减得到窗口分位数。
- 待发送 MSDU 在可验证情况下是否持续积压；当前全零不能证明它在负载下有用。

第一版只用它们识别“下行评分上升但上传明显恶化”的候选，作为拒绝提升/回滚的保护条件。上传主导的独立优化、双向加权目标留到验证后；不使用 radio TX airtime 冒充 STA 上传 airtime。

## 7. 候选调度与起始策略

### 7.1 不再从最大带宽重置

例：anchor=40 MHz，当前候选 160 的分数很差，80 也差。两次挑战分别输给新鲜的 40 基线，40 一直保留；不再因为 80 没比 160 快而误选 160。

例：160/80/40/20 的实际分数为 300/280/500/250。80 输后，40 仍保持可挑战资格；在后续有流量、有预算且环境稳定的轮次会测到它。保证的是候选不被永久饿死，不保证没有业务时在固定墙钟时间内收敛。

### 7.2 两层预算

- 稳定期通常仍至少间隔 15 min 发起一次普通挑战。
- 每个失败候选按 15/30/60/120/240 min 独立退避；不是只要“窄档赢过”就让所有候选一起延后。主信道/radio/协商能力改变时，旧性能历史失效；显著且持续的信号变化可缩短候选的性能退避，但不能绕过执行失败冷却和全局预算。
- 首版每次普通挑战最多一次外出和一次回滚；成功则留在候选。可疑结果先回滚而不立即再次挑战；受控校准的 A-B-A 不属于后台策略。
- 建议额外设全局上限，例如每 15 min 最多 2 次挑战开始。每次正常试验最多产生 2 次策略切换，即每 15 min 最多约 4 次宽度切换；执行重试另有原有上限。预算在进入候选前检查，必要回滚永远不被探索预算阻断。
- 速率下降一半只触发“提前获取新鲜基线并检查是否值得挑战”，不绕过冷却立即跳最宽档。
- 无证据的取消使用有限重试退避，防止视频分段下载不断触发试验；不要记为性能失败。

### 7.3 缓存与扫描先验

- 保留现有每网络最多 32 条的私密缓存。补充 score source、测量时信号、可信时间；不持久化大段统计日志。
- 现有 network id 已包含 BSSID、频率、SSID 的散列，沿用，不输出原始网络身份。
- 时间可信才按实际年龄降级缓存；离线重启时 RTC/UTC 不可靠，不能依赖错误墙钟判断“刚测过”。会话内截止时间使用单调时钟。
- 起点策略延续现有顺序：能力范围内的可用缓存优先，否则沿用扫描预测作为暂定起点；没有有效预测则用协商宽度。无论哪种起点，当前会话都重新建立 baseline；信号差异大、能力变化或记录老旧时更不能把历史选择当作结论。
- 扫描邻居预测只影响暂定起点和候选顺序，不排除其他合法候选；BSS 数量、单一 −82 dBm 门槛、未知邻居带宽都不足以证明实际占用。
- 复用用户连接时已有扫描结果，不为了提高先验而持续离信道扫描。
- 第一轮有业务时可做一次有预算挑战，后续走普通退避；不为“尽快学习”连续把四档试完。

## 8. 工程落点

不新增服务或重型依赖，保留现有三个边界：

1. `wifi_relay/llstats.rs`：一次读取解析出有明确 scope 的原始观测；保留缺失、无效、可用状态，不用零值替代缺失；补充 AC TX 解析须有真实脱敏 fixture。
2. `wifi_relay/width.rs`：窗口累积、固定锚点、单候选调度、预算和截止时间。状态机输入原始窗口/typed score，不再只接受脱离来源与时间的 `Option<u32>`。
3. `wifi_relay.rs::LinkWidth` / `Controller`：控制效果与读回、epoch、连接代次、watcher 接入和错误传播。保留已做好的有限重试与“确认后才缓存”。

设备 I/O 留在现有 blocking 路径，不放到 axum/tokio runtime；昂贵查询有界，不让统计阻塞掉线清理。正常 idle 不新增驱动轮询；已启动试验的收尾允许有限读回。UI 只读取已有状态快照，不新增无订阅的 events 采样器。

诊断只记状态变迁：匿名网络 id、旧/新宽度、原因、来源、窗口证据量、耗时、读回结果。日志有界，不每 3 s 刷一行，不记密码、token、原始 SSID/BSSID 或业务目的地址。

UI 文案可以区分：沿用历史起点、等待流量、比较中、已稳定、证据不足、无法确认/暂停。无需新按钮、图表或额外 CSS。

## 9. 分阶段实施与验收门槛

### 阶段 A：先修选择器，不扩大硬件控制面

实现固定锚点 + 一个挑战者 + 候选公平轮换/退避 + 窗口求和/新鲜度。暂不引入 survey、新 TX 决策、跨 BSS 切换。

拟议测试边界是纯选择器输入/输出、现有 LinkWidth 驱动适配边界、统计解析 fixture；具体测试边界在实施前与用户确认，本提案不修改测试或实现。

必须覆盖：

- 40 MHz 良好，160/80 一样差，复查不得丢掉 40。
- 20 MHz 稳定 → 40 较差 → 流量结束/超时，只回到原 20。
- 非单峰 300/280/500/250 不永久漏掉 40。
- 大小 airtime 样本的求和结果，不能退回均值比值。
- settling 不计分；合格坏样本早停；无流量不虚构失败。
- 延迟/失败读回、回滚失败、统计来源切换、计数重置、radio 迁移、用户取消都保留安全不变量。
- 预算不会阻止必要回滚；无效样本不能写缓存或提升候选。

### 阶段 B：只观察的评分校准

经另行同意的真机受控负载测试中，固定带宽，记录脱敏窗口数据；新评分先不驱动任何自动切换。

测试至少包含：STA 下载、热点客户端经中继下载、STA 空闲但热点独立上传、上下行混合、低速/分段业务。分别观察 2.4/5 GHz，确认：

- E 是否与同条件真实吞吐排序一致；共享 radio 混入是否可能反转排序。
- AC/per-rate TX 字段是否随本 STA 的上传变化，有没有重置/不刷新/重复累计。
- noise/survey 是否只有扫描后更新；如果没有可靠新鲜度，继续不用。
- LL 读取在实际负载下的最坏延迟和错误行为。

从固定带宽/受控业务实验得到的统计定义与阈值，才可以升级为生产选择依据。有限快照不是这一步的替代。

### 阶段 C：受控开启挑战器

经用户确认后再部署/切宽度，保留回滚版本。先保留 2.4 GHz 已知 20/40 改善，再验证 5 GHz 各候选。观察整个 LAN 客户端路径，不只看路由器本机。

验收目标：

- 试验失败后恢复已知锚点；驱动不确认时明确暂停，不假报成功。
- 不出现 160↔80 的周期循环把稳定 40 丢掉。
- 同条件交付吞吐不因自适应显著退化；同时观察时延、上传和连接中断，不只看平均下载。
- 真实空闲无额外 LL/PHY 轮询；分段业务不反复重启挑战。
- 统计丢失、上游切换、恢复/取消不拖住现有网络清理。
- 至少持续业务与混合业务的长时观察通过后，再放开默认启用；初始建议观察数小时，不宣称一次短测已覆盖。

### 阶段 D：独立后续议题，不绑进 V2

- 同 SSID/同安全能力下的 BSS/频段偏好：先提示和记录，不自动关联未知网络；需要用户政策和独立恢复验收。
- 上传主导的带宽目标：待 TX 统计及双向权衡验证后单独设计。
- Mihomo DIRECT 内核旁路：用户此前明确暂不做，仍排除。
- 5 GHz 重启关联/DFS/SAP-STA 并发可靠性：属于连接恢复问题，不能通过调优器重启热点掩盖。见 `2026-10-28-device-acceptance.md` 未通过的重启记录。

## 10. 成果与当前限制

本轮产出仅为设计与研究文档，未修改 `width.rs`、`llstats.rs`、`wifi_relay.rs`，未部署，未改变设备网络配置；没有用探测流量消耗蜂窝或上游流量。结束时再次读取接口，STA 5220/160、热点 5220/80 与 2462/40 均保持本轮开始的状态。先前本会话跑过的 25 项宽度测试，只证明旧实现已有回归通过，不代表本提案已经实现或验收。
